## IEC 60870-5-104 Protocol Behaviour

This document describes how the simulator implements IEC 60870-5-104, with a focus on behaviour that is important when testing IEC 104 masters/clients.

The simulator acts as an **outstation / controlled station** that listens on TCP port 2404 and exposes its configuration and state via a REST API.

---

## Basic configuration of IEC104 Server

| Appsetting             | Use                    | Default |
|------------------|---------------------------------|-------------|
| `CycleTimeMs`         |Time of simulation cycle in Milliseconds.  | 1000 |
| `Debug `         | Internal Debug logs of library  | false |
| `MaxQueueSize `         |  Sets the maximum size of the ASDU queue. The default implementation will drop the oldest ASDU | 1000 |
| `DataPointConfiguration `         |  Object containing Measures and Command Arrays | - |
| `DataPointConfiguration.Measures `         | IEC104 Datapoint Measurement | - |
| `DataPointConfiguration.Commands `         | IEC104 Datapoint Command | - |

## Core Concepts

### Common Address (CA) and Information Object Address (IOA)

- Every datapoint is identified by:
  - **Common Address (CA)** – station address
  - **Information Object Address (IOA)** – point address within the station
- In configuration (`SimulationOptions.json`) these are provided as strings and mapped to IEC addresses internally.

### Type IDs (ASDU Types)

The simulator supports a subset of IEC 60870-5-104 ASDU types that are most relevant for SCADA testing:

Measurements and indications:

- `M_SP_NA_1` (1) – Single point information
- `M_DP_NA_1` (3) – Double point information
- `M_ST_NA_1` (5) – Step position information
- `M_ME_NA_1` (9) – Normalized measured value
- `M_ME_NB_1` (11) – Scaled measured value
- `M_ME_NC_1` (13) – Short floating-point measured value

Commands:

- `C_SC_NA_1` (45) – Single command
- `C_DC_NA_1` (46) – Double command
- `C_RC_NA_1` (47) – Regulating step command
- `C_SE_NA_1` (48) – Set-point normalized
- `C_SE_NB_1` (49) – Set-point scaled

Other IEC types may be added over time; unsupported types are rejected with appropriate error causes.

## Simulation Modes

Each datapoint has a **simulation mode** that controls how its value evolves over time and when it is transmitted:

| Mode             | Transmission                    | Description |
|------------------|---------------------------------|-------------|
| `Static`         | On startup / interrogation only | Fixed value, never sent on the periodic cycle |
| `Periodic`       | Every cycle                     | Re-sends the current value with `COT = PERIODIC` |
| `RandomWalk`     | Every cycle                     | Value steps randomly by up to `FluctuationRate`, clamped to `MinValue`/`MaxValue` |
| `GaussianNoise`  | Every cycle                     | Gaussian noise around `BaseValue` ± `FluctuationRate`, bounded by `MinValue`/`MaxValue` |
| `PeriodicWave`   | Every cycle                     | Positive half-sine wave with period `WavePeriodSeconds`, peak at `BaseValue` |
| `Profile`        | Every cycle                     | Iterates through the inline `ProfileValues` array (loops continuously) |
| `EnergyCounter`  | Every cycle                     | Accumulates energy from a linked datapoint (`LinkedDataPointId`) each cycle |
| `CounterOnDemand`| On interrogation only           | Silently accumulates each cycle but only transmitted on GI/CI request |
| `CommandResponse`| On command receipt              | Mirrors an incoming command ASDU as a measurement response |

Periodic modes are driven by the simulator’s cyclic engine (`CycleTimeMs` in configuration). General interrogation (GI) is handled separately and described below.

## Value Initialization

The simulator ensures that every configured datapoint has a **concrete initial value** before any IEC 104 traffic is processed.

### Configuration-time initialization

On startup:

1. The configuration service loads datapoints from `SimulationOptions.json`.
2. Each datapoint is registered in an internal value repository.
3. If the datapoint already has a `Value` assigned, that value is preserved.
4. If no value is set, the repository uses the configured `InitValue` (or `InitString`) and the Type ID to create a default value object.

Default behaviour when `InitValue` is missing or invalid:

- Single points (`M_SP_*`) → `false`
- Double points (`M_DP_*`) → `OFF`
- Step positions (`M_ST_*`) → `0` within allowed range
- Scaled measured values (`M_ME_NB/TB/TE_1`) → `0`
- Short floating / normalized (`M_ME_NC/TC/TF_1`, `M_ME_NA/TA/ND_1`) → `0.0`

Because of this initialization step:

- There are no "uninitialized" datapoints in the IEC sense; every configured measurement has a defined value.
- General interrogation and cyclic transmission always return concrete values for configured and unfrozen datapoints.
- If you configure a datapoint with a Type ID that is not yet supported by the initialization logic, the simulator fails fast (throws) during configuration rather than producing partial IEC traffic.

## General Interrogation (GI)

General interrogation is a central feature of this simulator. It allows an IEC 104 master to retrieve a snapshot of all configured measurements from the simulated station.

### GI command basics

- **Type Identification**: GI command uses Type ID `100` (`C_IC_NA_1`).
- **Cause of Transmission (COT)**:
  - Master sends GI with `COT = ACTIVATION` (20).
  - Simulator replies with `COT = ACTIVATION_CON` (7).
  - When the GI sequence is finished, simulator sends `COT = ACTIVATION_TERMINATION` (10).
- **Qualifier of Interrogation (QOI)**:
  - Global interrogation (typically `QOI = 20`) is supported.
  - Group-specific QOI values (1–16) are accepted; currently the simulator treats them like global GI (no group-based filtering).

### GI execution in the simulator

When the master sends a GI command:

1. **Activation request** – Master sends `C_IC_NA_1` with `COT = ACTIVATION`.
2. **Activation confirmation** – Simulator immediately echoes the ASDU:
   - Same Type ID and addressing
   - `COT = ACTIVATION_CON`
   - `IsNegative = false`
3. **Measurement transmission** – Simulator collects all configured datapoints from its internal repository and sends their current values as measurement ASDUs:
   - Includes all datapoints configured in `SimulationOptions.json` that are not marked as **frozen**.
   - Groups values by Common Address (CA) and Type ID.
   - Splits each group into ASDUs with up to 20 information objects.
   - Sends these ASDUs with `COT = INTERROGATED_BY_STATION`.
4. **Activation termination** – After all measurements are queued, simulator sends the original GI ASDU again with:
   - `COT = ACTIVATION_TERMINATION`
   - Same Type ID and QOI as the original command.

This behaviour closely matches typical real-world IEC 104 outstations and is designed to make protocol and SCADA client testing straightforward.

## Command Handling

For supported command types (`C_SC_NA_1`, `C_DC_NA_1`, `C_RC_NA_1`, `C_SE_NA_1`, `C_SE_NB_1`):

- The simulator verifies that the command’s CA/IOA matches a configured command datapoint.
- If configured, it sends an **activation confirmation** (positive acknowledgement) for the command.
- If the command is linked to a simulated measurement (`CommandResponse` mode or `ResponseId`), the simulator generates a corresponding measurement ASDU to reflect the command effect.
- Unknown or unconfigured commands result in a negative response with the appropriate cause of transmission.

## Cyclic Transmission

The cyclic engine runs at `CycleTimeMs` and is responsible for periodic IEC 104 traffic:

- For periodic-style modes (`Periodic`, `RandomWalk`, `GaussianNoise`, `PeriodicWave`, `Profile`), it:
  - Computes new values per datapoint according to its mode.
  - Updates the internal repository.
  - Groups datapoints by CA and Type ID and sends measurement ASDUs with `COT = PERIODIC`.
- For counters:
  - `EnergyCounter` accumulates energy based on a linked power measurement each cycle and transmits the updated counter value.
  - `CounterOnDemand` accumulates silently each cycle but only transmits on GI.

Frozen datapoints are excluded from cyclic transmission and GI until they are unfrozen.
